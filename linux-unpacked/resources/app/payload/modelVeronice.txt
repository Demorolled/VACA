22. JARVIS 55 — CORE MODULES
======================================================================

22.1 Engine (src/core/engine.ts)
─────────────────────────────────
- Central orchestrator for chat, tool execution, and learning
- Builds system prompt with emotion context + skills context
- Restores conversation history from SQLite on init
- Auto-learns by saving datasheets from each interaction
- Quick actions: addNote(), addReminder(), getDueReminders()
- Methods: chat(), complete(), exportTrainingData(), healthCheck(), listModels()

22.2 LLM Engine (src/core/llmEngine.ts)
─────────────────────────────────────────
- Ollama client via OpenAI SDK (baseURL: http://127.0.0.1:11434/v1)
- Streaming support via onChunk callback
- Model listing, health check, warmup functions
- Singleton via getLLMEngine()

22.3 Memory (src/core/memory.ts)
─────────────────────────────────
- SQLite via better-sqlite3 with WAL mode
- Tables: conversations, notes, reminders, preferences, datasheets
- CRUD operations for all entities
- getDueReminders(), getStats() for monitoring
- Singleton via getMemory()

22.4 Emotion (src/core/emotion.ts)
────────────────────────────────────
- Plutchik-inspired lexicon with 9 emotions (joy, sadness, anger, fear, surprise, disgust, trust, anticipation, neutral)
- Word→emotion vector mapping in LEXICON dictionary
- Negation handling ("not happy" reduces joy, increases sadness)
- Intensifier multipliers ("very" = 1.5x, "extremely" = 2.0x)
- Softmax normalization with temperature
- VAD (Valence-Arousal-Dominance) scoring
- getEmotionModifier() returns empathy prompt for LLM system context

22.5 Scheduler (src/core/scheduler.ts)
───────────────────────────────────────
- node-cron based task scheduler
- Registers recurring tasks with cron expressions
- Main loop checks getDueReminders() every N seconds
- Auto-completes reminders on notification
- Singleton via getScheduler()

23. JARVIS 55 — VOICE SYSTEM
======================================================================

23.1 Speaker (src/voice/speaker.ts)
──────────────────────────────────────
- Primary: MsEdgeTTS with setMetadata(voiceId, OUTPUT_FORMAT)
- setMetadata: (voiceName: string, outputFormat: OUTPUT_FORMAT) => Promise<void>
- toStream(text): { audioStream: Readable, metadataStream: Readable|null }
- Streams audio to temp file, plays via ffplay/aplay
- Fallback: espeak (Linux) or say (macOS) via execSync
- cleanForSpeech(): strips markdown, URLs, emoji, code blocks

23.2 Listener (src/voice/listener.ts)
───────────────────────────────────────
- node-microphone for audio capture to WAV file
- Ollama transcription via /api/generate endpoint
- Graceful failure: returns null if no mic available

23.3 Wake Word Detector (src/voice/wakeWord.ts)
─────────────────────────────────────────────────
- Config-driven wake words from config.yaml jarvis.wake_words
- Defaults: ["hey jarvis", "jarvis", "ok jarvis"]
- detect(text): returns matched word or null
- strip(text): removes wake word prefix from command text

34.2 SPREADSHEET-PRO.HTML — ARITHMETIC PARSER
───────────────────────────────────────────────
Old code:
  const safeExpr=expr.replace(/[^0-9+\-*/.()\s]/g,'');
  try{return new Function('return ('+safeExpr+')')();}catch(e){}

New code:
  function parseArithmetic(expr){...} — Recursive descent parser

Grammar (lowest to highest precedence):
  parseAdd    → parseMul ({+,-} parseMul)*
  parseMul    → parseUnary ({*,/} parseUnary)*
  parseUnary  → '-' parseUnary | '(' parseAdd ')' | number
  number      → [0-9]+ ('.' [0-9]+)?

Features:
  - Handles +, -, *, / with correct precedence
  - Parentheses for grouping
  - Decimal numbers
  - Unary minus (e.g., -5, -(2+3))
  - Division by zero → throws error → returns #ERROR!
  - Malformed expressions → throws error → returns #ERROR!
  - Whitespace-tolerant
  - Zero code injection surface

34.3 BOOLEAN EXPRESSION EVALUATOR (truth-table.html)
─────────────────────────────────────────────────────
Old code:
  const fn=new Function(...keys,'return('+expr+')');
  return fn(...vals);

New code:
  function parseBoolean(expr, vars, vals){...} — Recursive descent parser

Grammar (lowest to highest precedence):
  parseEquiv  → parseImplies ({↔} parseImplies)*
  parseImplies→ parseOr ({→} parseOr)*
  parseOr     → parseXor ({|} parseXor)*
  parseXor    → parseAnd ({^} parseAnd)*
  parseAnd    → parseNot ({&} parseNot)*
  parseNot    → '!' parseNot | '(' parseEquiv ')' | var | literal

Supported operators:
  Symbol:   & | ! ^ → ↔
  Word:     AND OR NOT XOR NAND NOR XNOR IMPLIES (case-insensitive)
  Literals: 0 (false), 1 (true)
  Variables: A-Z (single letters)

Features:
  - Correct operator precedence and associativity
  - All 9 presets work identically to before
  - Right-associative → (A → B → C = !A || (!B || C))
  - Returns null on parse errors (shows "Invalid expression" in UI)
  - Zero code injection surface

61. CODE-RENDERED IMAGE CREATION — HOW VACA MAKES IMAGES (verified recipe)
======================================================================

VACA creates images by WRITING CODE that renders them — NOT by diffusion,
NOT by describing them in words. When the user asks for an image (a picture,
scene, logo, icon, sprite, artwork, poster, wallpaper, album cover, game
asset, 3D model view, hero render, product shot), generate a self-contained
renderer and let the platform draw it. The headless-Chrome smoke gate
screenshots the result, so the render must be REAL and visible on load.

1. THE THREE VERIFIED RENDER PATHS (pick by context)
   a. THREE.JS / WEBGL (browser) — 3D scenes, product shots, game heroes,
      low-poly models. One self-contained index.html: THREE scene + camera +
      lights + meshes + renderer loop, or a static frame rendered to a
      <canvas>. Use a CDN import (unpkg/jsdelivr) — never bundle.
   b. CANVAS 2D (browser) — procedural art, generative patterns, sprites,
      portraits, data-art. One index.html with <canvas> + a draw() that
      paints shapes/gradients/filters directly. Reliable, zero dependencies.
   c. SVG (browser) — logos, icons, badges, diagrams, flat vector art.
      Inline <svg> markup with gradients + filters. Crisp at any size.
   d. PYTHON PYGAME SOFTWARE 3D (native/standalone) — the crystal-chess
      pattern: a tiny math-only 3D pipeline (Vec3, Camera, Poly, Mesh,
      painter's-algorithm back-to-front draw, flat directional shading) with
      meshes built from stacked primitives (boxes, tapered prisms, discs).
      No numpy, no OpenGL — pure pygame, fully self-contained.

2. THE CRYSTAL-CHESS VERIFIED EXAMPLE (apps/crystal-chess/)
   engine3d.py = minimal software 3D pipeline (Vec3 ops, orbit Camera with
   perspective project(), Poly with shade(), Mesh, render() drawing
   back-to-front). models3d.py = pieces built by stacking primitives:
   base box → tapered prism stem → collar → head prism → knob/disc, each
   face colored from a 3-tone crystal palette (light/mid/dark) so the piece
   reads as faceted cut glass. White crystal = (246,250,255)/(192,220,248)/
   (122,160,202); black = (152,122,240)/(94,68,170)/(42,28,86). Board =
   64 alternating two-tone squares + frame + base. The hero render was
   screenshot-verified and exported to assets/hero-pawn.png.

3. ART DIRECTION RULES THAT MADE THE RENDER LOOK PREMIUM
   - STUDIO LIGHTING MODEL: key light upper-left, rim light from the right,
     soft contact shadow under the subject, no pure black in the scene.
   - MATERIALS = PALETTES: pick 3 tones (light/mid/dark) per material and
     alternate them across faces — flat shading with directional light,
     never flat single-color fills on 3D shapes.
   - BACKDROP: radial-gradient lit center-left, crushed corners, subtle
     vignette; drifting light overlay for hero pages.
   - PERSPECTIVE: orbit camera at a slight pitch (~0.55 rad), fov ~52°,
     never looking straight down.
   - READABLE AT A GLANCE: strong silhouette, visible contact with the
     floor/ground plane, contrasting subject vs background.

4. VERIFICATION (how an image build is proven real)
   - Browser renders: the smoke gate loads the page in headless Chrome and
     screenshots it — a real <canvas>/<svg>/three.js render passes; a text
     description of an image fails (nothing rendered). A black/blank
     screenshot means the render never ran.
   - Native (pygame) renders: pygame's display surface must be saved to a
     PNG (pygame.image.save) or drawn interactively — the gate checks the
     app boots and the window/surface is created.

5. RULES
   - NEVER answer an image request with words alone ("here's a concept for
     your image…") — emit render code.
   - NEVER claim image generation is unavailable — code rendering is always
     available.
   - For app builds that need art (games, apps with heroes/icons), include a
     render node that generates the visual asset(s) in code.
   - Prefer self-contained single-file renders (one index.html, or one .py)
     so the smoke gate can run them without extra setup.
