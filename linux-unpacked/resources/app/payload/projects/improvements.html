🚨 Phase 1 — Critical Fixes (Week 1)

Highest impact, lowest effort. These are the must-fix items before anything else.

1.1 Fix XSS in App Generation Pipeline Quick fix

CRITICAL Problem: 3 generated apps (expense-tracker, chat-app, kanban-board) use innerHTML with unsanitized user input. The CodeScanner.ts already detects this pattern but doesn't prevent it during generation.

Fix: Add HTML entity escaping as a post-generation step in the scaffolder:

// Add this utility to scaffolder.ts
function escapeHtml(str) {
  return str.replace(/&/g, '&')
            .replace(//g, '>')
            .replace(/"/g, '"')
            .replace(/'/g, ''');
}

// Run securityScan on generated HTML before writing
// Auto-fix innerHTML assignments with escaped content

Bonus: The previewHtmlBuilder.ts already has an escapeHtml() function — reuse it in the scaffolder for generated app output.

1.2 Automatic Post-Gen Security Scan Quick fix

CRITICAL Problem: The CodeScanner.securityScan() method already exists and detects XSS, eval(), SQL injection, and 12 other vulnerability types — but it's not automatically called after code generation.

Fix: Add a postGenerationScan step in the generation pipeline that:

  1. Runs securityScan() on every generated file
  2. Blocks deployment if critical/high vulnerabilities found
  3. Returns scan report to the user with remediation suggestions

Impact: Zero new code needed — just wire up the existing scanner into the generation pipeline.

1.3 Replace eval() in Sandbox with Safe Runner Medium effort

CRITICAL Problem: The sandbox preview uses eval(appCode) to run generated JavaScript. This is a security risk — generated code could access the parent window's DOM, localStorage, or cookies.

Fix: Replace eval() with an iframe-based sandbox:

// Instead of: eval(appCode);
// Use:
const iframe = document.createElement('iframe');
iframe.sandbox = 'allow-scripts allow-same-origin';
iframe.srcdoc = `<script>${appCode}</script>`;
iframe.style.display = 'none';
document.body.appendChild(iframe);

Impact: Prevents sandbox code from accessing the parent application entirely.

⚡ Phase 2 — Core Architecture (Week 2-3)

Medium effort, high impact. These improve reliability, accuracy, and user experience.

2.1 App Testing Automation Medium effort

HIGH Problem: Apps were tested manually via browser — no automated test harness exists. This makes regression testing impossible.

Fix: Create an automated app test suite that:

  1. Launches each HTML app in a headless browser (Puppeteer/Playwright)
  2. Checks for: page load, console errors, interactive elements, keyboard nav
  3. Generates a test report with pass/fail for each app
  4. Runs on every code generation to catch regressions

Suggested tool: Vitest + Playwright (already have Vitest in deps)

2.2 Timer Accuracy Fix Quick fix

HIGH Problem: Multiple apps use setInterval(fn, 1000) which drifts over time. The pomodoro timer could be off by 3-5 seconds after 25 minutes.

Fix: Replace with Date.now() differential pattern:

// Instead of:
setInterval(() => { timeLeft--; }, 1000);

// Use:
const startTime = Date.now();
const duration = 25 * 60 * 1000;
setInterval(() => {
  const elapsed = Date.now() - startTime;
  const remaining = Math.max(0, duration - elapsed);
  updateDisplay(Math.ceil(remaining / 1000));
  if (remaining <= 0) onComplete();
}, 100); // check every 100ms for accuracy

Apps affected: pomodoro-timer, music-player, typing-test

2.3 Add Accessibility Scaffold to Generated Apps Medium effort

HIGH Problem: All 24 apps lack ARIA labels, proper heading hierarchy, and keyboard navigation support.

Fix: Create an accessibility plugin for the scaffolder that automatically adds:

  • lang="en" attribute to all HTML documents
  • role="button" and aria-label on interactive elements
  • tabindex and keyboard event handlers
  • Focus management for modals and dynamic content
  • Color contrast verification (WCAG 2.1 AA compliance)

2.4 Mobile Touch Support for Kanban Medium effort

MEDIUM Problem: HTML5 Drag and Drop API doesn't work on touch devices. The kanban board is unusable on mobile.

Fix: Add touch event handlers (touchstart, touchmove, touchend) that mirror the drag/drop behavior. Use elementFromPoint() to detect drop targets on touch devices.

🚀 Phase 3 — Advanced Features (Week 4-6)

Larger efforts that unlock major capability improvements.

3.1 Multi-Framework App Generation Templates Big effort

MEDIUM Problem: Currently all apps are vanilla HTML/CSS/JS. No React, Vue, Svelte, or Next.js support.

Fix: Extend the scaffolder with template engines:

  • React: Generate JSX components with Vite build config
  • Vue: Generate SFC (.vue) files with Vite
  • Svelte: Generate .svelte files
  • Next.js: Generate pages/api structure

Piggyback on existing system: The node types and data flow already exist — just swap the output template.

3.2 Interactive Live Preview Big effort

MEDIUM Problem: The sandbox preview is a static HTML page. Users can't see changes as they edit nodes.

Fix: Implement WebSocket-based live preview that:

  1. Streams code changes in real-time as nodes are edited
  2. Hot-reloads the preview without full page refresh
  3. Shows compilation errors inline in the node editor

Architecture: The socket.io-client is already in package.json — just need a Socket.IO server for streaming code changes.

3.3 AI-Powered Fix Suggestions Big effort

MEDIUM Problem: When code generation produces errors, the user sees raw error messages with no guidance on how to fix them.

Fix: Pipe CodeScanner results + error output into the LLM to generate human-readable fix suggestions:

1. Run generated code → catch errors
2. Run CodeScanner → get vulnerability report
3. Send both to LLM: "Here's the code, here's the error,
   here are security issues found. Suggest fixes."
4. Display fix suggestions with diff view

3.4 Backend Reliability & Offline Mode Big effort

CRITICAL Problem: Backend went down multiple times during testing. No offline fallback — entire app breaks when backend is unavailable.

Fix: Multi-pronged approach:

  • Retry with exponential backoff: All API calls retry 3× with 1s/2s/4s delays
  • Offline queue: Queue failed operations and replay when backend recovers
  • Local-only mode: Detect backend status and fall back to localStorage for all operations
  • Health endpoint: Add /api/health with DB connection check, disk space, uptime
